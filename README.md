# 雨夜 · Mira

移动端优先的开放式语音相遇。暴雨夜的咖啡馆是起点；故事沿着对话生成，没有固定事件池、预设路线或五分钟强制结局。可以参与新事件、提出选项之外的行动、去新的地方，也可以安静坐着。

## 快速开始

```bash
pnpm install && pnpm dev
```

打开 http://localhost:5173 。真实语音与剧情需要 `.env` 里的 `DOUBAO_API_KEY`（豆包 Duplex 语音）和 `SEED_API_KEY`（方舟：导演 LLM + Seedream 生图），见 `.env.example`。

**没有 API key 也能体验核心流程**：`pnpm dev` 后访问 `http://localhost:5173/?mock=1`，回放一段真实会话的完整录制——语音、字幕、舞台指令、打断、生图事件按原时间轴重放。它不生成新内容，但完整展示状态机与演出管线。

手机与开发机同一网络时需可访问的 HTTPS 地址（浏览器麦克风要求安全上下文）；localhost 仅指设备自身。

## 系统结构

双 agent（演员 + 导演）+ 客户端导演，三条通道各司其职：

```
浏览器 (React + R3F) —— 呈现层，管"画什么"
  ├─ ClientDirector 状态机: idle⇄listening→thinking→speaking
  ├─ 队列调度: 字幕流 / 舞台指令 / 媒体事件（指令随 tool call 到达即入队）
  ├─ VRM Mira (three-vrm) 叠加 AI 生成场景；下行音频振幅→口型
  └─ 打断: 本地能量 VAD / 服务端转写信号 / 手动按钮 → 停音频清队 → 上行 interrupt
        ↕ 自有 WS 协议（JSON 消息 + 二进制 PCM 帧，shared/protocol.ts）
Node 服务端 —— 导演 agent，管"演什么"
  ├─ ClientSession: 浏览器⇄Duplex 桥接、打断仲裁、会话恢复、录制回放
  ├─ Director: 对话记忆 + 静默契机 + 世界决策（豆包文本 LLM，单行 JSON 决策）
  └─ genimg: 生图管线（风格模板 → 质检 → 重试 → 降级 → 缓存）
        ↕ 火山 Duplex WS（JSON 事件）
豆包 Duplex —— 演员，管"怎么说"
  ├─ instructions = Mira 人设卡 + 表演规则（content/persona.mira.md）
  ├─ 原生: server VAD / 附和抗干扰 / 打断 / 情绪声线涌现
  └─ tools = 结构化场景指令通道
```

主要模块：

| 模块                              | 职责                                                                                                                                          |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `server/src/session.ts`           | 一场戏的全部编排：打断仲裁（可疑响应暂扣观察窗、迟到音频丢弃、6s 打断宽限窗）、转写流、工具调用分发、断线重连                                 |
| `server/src/director.ts`          | 导演：对话记忆、静默契机注入、世界决策、照片/场景调度、剧情阶段                                                                               |
| `server/src/duplex.ts`            | Duplex 协议客户端：20ms 音频节拍、注入通道（递词/旁白/回合）、工具回传、指令解析与物理校正                                                    |
| `server/src/genimg.ts`            | 生图管线：主题×风格模板 → 生成 → 像素方差质检 → 重试 → 剧情化降级 → 按 scene_key 缓存                                                         |
| `web/src/state/directorClient.ts` | 客户端导演：状态机、epoch 守卫丢迟到包、本地 VAD、媒体事件调度（图片预加载成功才转场）                                                        |
| `web/src/audio/engine.ts`         | 采集/播放/环境音；播放缓冲实测决定"说完"时刻并回报服务端                                                                                      |
| `web/src/scene/`                  | `VrmActor`+`actor`：角色渲染层（情绪 blendshape、原子姿态插值、振幅口型、眨眼/呼吸/视线）；`Stage`/`Background`/`Rain`/`CameraRig` 场景与运镜 |
| `content/`                        | 内容层：人设卡、导演提示词、风格模板、兜底台词（配置驱动，改文案不改代码）                                                                    |

## 语音交互与打断

- **语音回合**：浏览器 PCM16k 单声道 20ms 帧 → 服务端 → Duplex。服务端 VAD 产出用户转写流（字幕）、角色音频流与文本流（同步字幕）。
- **文字回合**：文字 → 导演生成 Mira 回应 → `speech_text_buffer.commit` 念出。协议没有 `response.create`，递词走诚实通道，不伪造麦克风输入；字幕由服务端直发。
- **多轮**：会话内保留最近对话、用户原话事实、Mira 已说经历、未回应话语与已确认事件后果；中断的回答不视为完整告知。

打断选择**自动 VAD（双源）+ 手动按钮**，不用按住说话：

- 场景是"面对面对话"而非对讲机——按住说话会破坏开放陪伴式体验，用户需要随时能开口。
- **本地源**（AnalyserNode 能量 >300ms）快但有噪声误判风险；**服务端源**（`transcription.started`，官方注明可用于打断）准但有网络延迟。双源任一先到即触发，互为兜底。
- 手动"打断"按钮是第三重保险：VAD 全失效或用户不想出声时仍可用。
- 打断语义：停全部音频源 + epoch++ 作废在途指令/字幕/媒体 → 上行 `interrupt` → 服务端 `cancelResponse` + 清注入队列 → 回 listening。迟到音频/文本按 rid/epoch 守卫丢弃，上一轮迟到响应不会覆盖当前状态。
- 关键坑：Duplex 下行音频是**突发式**下发（3.5s 语音约 450ms 内发完），`output_audio.done` ≠ 用户感知的说完。所以播放结束由浏览器音频缓冲实测回报，服务端在 done 后保留 6s 打断宽限窗；打断余波中到达的新响应暂扣 400ms 观察窗，存活才放行——避免半截"嘟"声残片。

## 角色与场景指令

指令走 Duplex function tools，随回复流式到达即入队：

| tool              | 参数                                                                 | 落到                                           |
| ----------------- | -------------------------------------------------------------------- | ---------------------------------------------- |
| `stage_directive` | `emotion`(6 种) / `gesture` / `motion` / `camera`(5 种) / `fx`(4 种) | 表情 blendshape、骨骼姿态、运镜、环境层        |
| `scene_event`     | `theme`                                                              | 地点转换 → 服务端生图 → 浏览器确认可显示才转场 |
| `show_photo`      | `subject`, `caption`                                                 | "掏照片" → 生图道具浮层                        |

姿态不是枚举动作，是**原子槽位**：手到空间锚点、躯干/头连续量、视线目标、手持物。`{hand_l:'forward_eye', prop:'photo', gaze:'user'}` = 把照片递到你眼前。模型自由组合，服务端按物理规则校正怪组合，并把砍掉的字段随工具回执返给模型——它能看到"被砍了什么"自行收敛。

视觉事件与对话绑定而非计时器：`show_photo` 由演员模型在台词到点时自发调用；若台词递了照片却漏调，`armPhotoFromSpeech` 兜底补生成。场景转换由导演世界决策驱动：确认行动 → 生成 → 浏览器图片加载成功 → 才换地点，中途任何一步失败都留在原处，永不黑屏。

## 模型与第三方服务

| 用途                           | 服务                                                                           |
| ------------------------------ | ------------------------------------------------------------------------------ |
| 语音对话（ASR+LLM+TTS 全双工） | 豆包端到端 Duplex（`openspeech.bytedance.com/api/v3/duplex`，model `1.2.6.1`） |
| 导演 LLM（世界决策/文字回应）  | 火山方舟 `doubao-seed-1-6-flash`                                               |
| 生图（照片/叠层/新场景/前景）  | 火山方舟 Seedream `doubao-seedream-4-5`                                        |
| 角色模型                       | 开源 VRM 示例模型（`assets/mira.vrm`，可整只替换）                             |
| "对视"人脸追踪                 | MediaPipe FaceLandmarker，全程本地推理，画面不出浏览器                         |
| 环境音                         | ffmpeg 程序化合成（雨声/咖啡馆 BGM，来源见 `assets/audio/SOURCES.md`）         |

密钥只在服务端 `.env`，不进仓库、不下发客户端。

## 关键技术取舍

- **端到端语音模型而非 STT+LLM+TTS 拼装**：VAD、转写、打断、情绪声线都是模型原生能力，延迟与打断质量远好于自拼管线；代价是协议约束硬（20ms 节拍、mute 保活、无 `response.create`）。
- **文字回合递词而非伪注入音频**：诚实通道、实现简单；代价是文字回合的情绪声线弱于真语音回合。
- **振幅口型而非音素级**：下行音频直接喂 AnalyserNode，零成本且够自然；协议无字级时间戳，音素口型留给演进。
- **原子姿态而非枚举动作**：模型自由组合身体槽位，服务端校正；比固定动作库表达面广，比直接暴露骨骼数据安全。
- **生图不阻塞语音**：`media.event` 异步下发，生成中状态浮层呈现；转场三重确认保证永不黑屏，代价是地点切换有数秒可见延迟。
- **进程内存会话**：部署固定单实例，换来实现简单；代价是无水平扩展与跨天持久记忆。

pnpm exec tsx scripts/verify-voice-live.ts   # 合成输入 → 真实 ASR/语音/打断恢复
pnpm exec tsx scripts/verify-world-live.ts   # 真实模型的事件及自由行动决策
pnpm exec tsx scripts/verify-media-live.ts   # 真实生图和转场链路（调用付费服务）

验证记录在 `output/checks/`，手机/桌面截图在 `output/playwright/`。浏览器触摸模拟不是实体手机验收；合成语音测试不能证明真实环境的回声消除与噪声表现。

## 已知问题

- 中文 ASR 对合成 TTS 测试音频偶有丢句；真实人声正常。
- 回声消除依赖浏览器 AEC；外放 + 嘈杂环境的真机表现未充分验证。
- 角色是 VRM 示例模型（机械臂设定的 Seed-san），不是拟人皮；换模只需替换 `assets/mira.vrm` 并保持骨骼/表情命名兼容。
- 二维场景 + 三维人物的透视与画风一致性还需持续调校。
- 开放剧情不保证所有长对话无矛盾（有事实记录、过期校验、明确行动检查兜底）。
- 世界状态仅在当前服务进程会话内保留，服务端重启即新相遇，无跨天持久记忆。

## 上线部署

根目录 `Dockerfile` 可直接用于 Railway / Zeabur / Render 等容器平台（自动识别构建）：

- 构建期 `pnpm install --frozen-lockfile && pnpm build`，启动命令 `pnpm start`；平台注入 `PORT`。
- 实例数固定 1（会话在进程内存）；`cache/`、`recordings/` 用临时盘即可。
- 环境变量：`DOUBAO_API_KEY`、`SEED_API_KEY`；`ACCESS_TOKENS`（逗号分隔的访问口令，设置后 `/api/*`、`/media/*`、`/mock/*`、`/ws` 需先凭口令换 cookie）；`MAX_SESSIONS`（默认 10）。
- 平台提供 HTTPS 域名后，手机端麦克风可用。

`GET /api/logs` 与右上角调试入口可查看运行日志；日志含对话内容，仅用于本地开发。

## 投入时间与两周演进

大致投入约 3 天（72 小时窗口内，AI 结对编程，分工见 `AI_USAGE.md`）：协议探针与架构约半天，核心链路（语音/打断/指令/生图）约一天半，开放世界改造、移动端适配与验证打磨约一天。

如果继续开发两周：

- **角色**：换拟人 VRM/GLB（Meshy+Blender 管线已验证可插拔）；音素级口型；VRMA/Mixamo 动作库（`motion` 协议层已预留，只换客户端实现）。
- **视频演出**：Seedance 生成关键剧情片段（方舟 key 已实测 1.0–2.5 可用）；全屏片段与常驻角色的衔接、失败降级到现有动画。
- **语音**：回声/噪声真机矩阵测试；附和与真打断的细分策略；首包延迟与关键阶段耗时观测页。
- **会话**：录制回放导出为可分享链接；跨会话持久记忆（用户事实库）。
- **工程**：模型/媒体 provider 可替换抽象收拢（目前已走 env 可换）；会话回放诊断页；更多端到端自动化测试。
