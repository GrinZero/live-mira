## 1. 产品目标与本轮结论

保留 Node + Duplex 演员 + 导演 LLM + React/R3F/VRM + Seedream 生成图片的架构。将图片场景升级为“生成外观 + 经校准的局部交互空间”，先完成桌边持续相处，不要求生成整间可自由探索的 3D 房间。

体验目标：用户开口可以改变她正在做的事情；用户不说话时，她仍有自然行为，且允许长时间安静。人物、语言、物品和环境对同一件事保持一致。

优先完成坐在桌边的拿杯、放杯、看窗、递照片及其中断，再考虑远距离走动和关窗。不能用增加随机动作或定时台词替代行为闭环。

## 3. 图片场景如何支持拿杯子

### 3.1 一张图拆成四类职责

1. **环境底图**：生成的窗外、墙壁、远景家具和整体气氛。需移除将要独立交互的物品，形成干净底图。
2. **遮挡层**：桌沿、窗框等需要挡住身体的区域，使用同一版干净底图生成遮罩；不能复用仍含原杯子的前景图。
3. **简化几何**：桌面平面、必要的桌沿遮挡体、座位锚点和有限地面。负责接触、局部阴影、命中和可达性，未必全部可见。
4. **独立对象**：杯子使用低复杂度 3D 网格；照片使用生成图片作为薄片网格纹理；手机可用简单网格。独立渲染位置、归属和状态。

杯子的具体处理：保留原图，派生去杯底图，尽量保留碟子和桌面纹理；将独立杯子落在原碟子上。去除杯子投影/反射残留，避免双重阴影。若原碟子透视无法对齐，再把杯碟一起独立化。第一版相机留在图片里，不声称它可拿取。

在第一次拿杯之前，杯子就必须以独立对象显示。不能在抓取那一帧用生图把原杯子擦掉，也不能每次喝水重新生成场景。

### 3.2 统一投影，避免“看起来放上去了”

一个 SceneProfile 绑定底图版本、参考相机、图片裁切、桌面几何、座位/手部目标、遮罩和灯光。单张图片不能精确恢复整个房间，只校准镜头能看到的局部。

背景源图坐标先经统一 cover 裁切映射到屏幕，再与 3D 参考相机投影对齐。背景、桌子、杯子、手不能分别按 CSS 百分比独立移动。横竖屏使用同一空间标定及明确的取景规则；必要时选择分别校准的两套镜头。

互动期间限制镜头自由度。推近优先采用统一画面裁切/缩放，避免只推 3D 相机、背景仍静止而改变杯子与桌面的相对位置。先关闭或统一桌边背景与物品的独立视差。头部追踪可以控制人物视线，不自动变成大幅相机移动。

灯光匹配现有暖灯与冷窗，杯子增加局部接触阴影。与手、人物之间使用同一 3D 深度测试；桌沿使用匹配的深度遮挡体或分区遮罩。当前整条 DOM 前景可能把伸向用户的手和杯子一起盖住，需按前后关系改造。

### 3.3 任意新生成图片怎么办

保留自由换景，但每个地点声明实际能力：

- **环境级**：新图加载成功即可聊天、转向用户、做不依赖场景接触的姿态。看向窗等动作需要有效目标，否则不提供。
- **局部互动级**：有验证过的桌面、道具、接触点和遮挡，才允许拿放物品。
- **移动级**：有验证过的路线、站位及镜头范围，才允许穿过画面或接近门窗。

后续可以用固定布局模板生成不同风格房间，预留桌边交互区域；生图仍可能偏离约束，必须做对齐检查。视觉模型提供的桌角/物体位置只能作为候选，不直接开放抓取。没有通过校准时保留环境级能力，不阻塞原有聊天和换景。

不能仅根据“这是咖啡馆”给所有图片套同一张桌子的坐标。第一版只手工校准当前咖啡馆，验证方法后再扩展。

### 3.4 跨地点复用空间模板

先建立桌边、屋檐下/街边、窗边/观景处三类空间模板。每个模板定义活动区域、独立道具/必要近景、接触锚点、遮挡、灯光和镜头边界；生图负责环境外观。模板的关键接触面优先由独立资产控制，避免每次重新匹配图片里随机生成的桌子。

地点创建时固定选择模板及版本。图片偏离布局时须校准或降级，不能因为选择了模板就假定生成图片一定匹配。返回旧地点复用已保存的底图、模板和对象状态，不重新生成一个相似地点。

## 4. 从姿态指令到完整行为

增加 `SceneProfile`、`ObjectState`、`BehaviorTask` 三类数据；下面是字段草案，不是已可用协议。

| 数据         | 必需信息                                                                                                                          |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| SceneProfile | locationId、profileVersion、assetVersion、referenceCamera、crop、anchors、surfaces、occluders、capabilities                       |
| ObjectState  | objectId、kind、owner（locationSurface/characterHand/inventory）、locationId 或 characterId、anchorId、transform、state、revision |
| BehaviorTask | taskId、intentId、sceneInstanceId、targetId、phase、resourceLocks、checkpoint、status                                             |

导演输出 `pick_up(cup_01)`、`put_down(cup_01, table_rest)`，执行器检查是否存在、手是否空闲、距离是否可达。模型不输出骨骼角度或任意坐标。

拿杯阶段：准备 → 看向杯子 → 伸手 → 接触 → 抓持 → 抬起 → 稳定持有。基础动画提供自然动作，手部 IK 对齐杯把/抓握锚点；接触阶段才把归属从桌面切到手。放下则在杯底到达桌面时提交归属变化。

到达接触点、持物切换、最终完成分别回报。动画播放结束不自动等于成功。资源锁至少涵盖左右手、躯干/移动；眼神可独立响应，满手持物时不插入挠头动作。持续姿态不能因原有 hold_ms 到期让手回 rest 并丢下物品。

语音与行为有两种关系：开始时可以说“好，我拿给你”；只有收到完成回报后才能说“给你了”。新增动作执行 tool 时即时回执只表示已接受，后续结果作为现场事实注入，再决定是否需要补话。失败时不编造已经完成。

## 5. 打断：语音停了，世界不会回滚

将语音 response/epoch、行为 taskId、场景 sceneInstanceId 分开。清语音队列不删除实际持物状态，不撤销已关上的窗，也不允许旧任务完成回报进入新地点。

用户发声的本地反馈先于完整转写：结束/压低当前说话，转向用户；运动进入合适的安全停顿。识别明确意图后选择继续、暂停、取消或替换。普通插话不自动取消原任务。

| 打断时刻       | 身体与物体                                    | 后续                         |
| -------------- | --------------------------------------------- | ---------------------------- |
| 伸手但未接触   | 减速、停手或收手；杯子仍在桌上                | 取消或从可恢复阶段继续       |
| 接触提交附近   | 用单一、幂等提交决定归属；不能手/桌各出现一只 | 回报最后确定状态             |
| 已拿起         | 稳住杯子并看向用户                            | 等要求，不突然回待机         |
| 正在喝         | 先离开嘴边，转为持杯，再说话                  | 视请求继续喝或放下           |
| 放杯中         | 若已近桌面，先完成安全放置                    | 完成状态保留；后续任务可取消 |
| 只是问一个问题 | 保持不冲突的动作                              | 可以边做边回答               |

声音活动检测在 speaking 以外也要通知行为执行器。噪声/附和不能直接取消任务；误判可在没有有效转写、没有明确取消请求时从检查点恢复。暂停等待要有有界策略，不能拿杯僵住无限久。

换景时先处理持物：允许随身带走的对象保留同一 ID，其余明确放下或阻止转场开始；取消未完成的旧场景行为。保留现有图片预加载与 scene.presented 确认，但媒体加载和世界状态提交分开。

断线/重连使用服务端认可的对象快照恢复，不能重播一次拾取导致重复物体。客户端回报必须校验任务、场景、阶段顺序和重复事件；长时间没有 ACK 标记 unknown/reconciling，不能直接宣告成功。一次会话仅有一个行为执行客户端作为当前权威。

## 6. 环境反应和沉默主动性

### 环境反应

引入有 ID 的环境事件，例如雷声、灯暗、雨势变化。一个事件驱动视觉/声音时间线，同时进入人物感知。闪光与雷声可分时到达；角色不能在雷声真正播放之前凭空说“这雷真响”。素材加载失败也不能回报已经听见。

本地身体反应按强度、近期重复次数和当前动作选择：轻微目光变化、停顿、稳定杯子。导演在后续判断是否值得说话。一个事件只反应一次；小环境变化可被忽略，不把每次环境效果都变成剧情邀请。

### 主动行为

保留当前 cadence 的播放结束 ACK、revision、用户活动作废和有限续话门禁。扩展决策上下文和输出，避免另起一个会与现有计时器争抢话轮的系统。

上下文新增：当前任务及检查点、可用对象、刚发生但未回应的事件、是否在等用户答复、主动内容被忽略次数、用户表达的安静偏好。

候选结果：等待、安静观察、执行一个低打扰行为、继续上一句、就现场发起一句话。优先级：明确用户请求 > 当前行为的安全完成/暂停 > 环境即时反应 > 主动活动。

沉默时长只是门禁。用户刚被问问题则等；话题已结束可以喝咖啡、看雨；已无回应的主动话题不换个说法再问。连续未回应后拉长间隔，直到用户重新参与。低打扰行为也检查资源锁和重复冷却，不固定循环“看窗—喝水—看你”。

用户说“安静一会儿”后停止主动台词，保留必要的小动作；没有新事件时可以长期没有新台词。规划期间用户开始讲话，旧计划作废，不会等模型晚回包后突然插话。

## 7. 雷声：素材与排查计划

当前只有三条循环轨：rain_loop、rain_heavy、cafe_bgm。雨声文档标注真实录音，不能在没有试听证据时称它是合成噪声。视觉闪电没有独立声音绑定。异常声可能涉及素材片段、叠层、实际部署版本等，目前不下结论。

本轮已获取候选素材 `assets/audio/sources/thunder-3179.mp3`：BigSoundBank Thunder #6，Joseph SARDIN & Axeline T.，页面描述单次雷声、无雨、户外，列出录音器材，许可 CC0。下载的是 MP3 分发版，不冒称原始 WAV。ffprobe 验证 13.8272 秒、48 kHz、单声道；未完成主观试听和场景混音验收。

来源：https://bigsoundbank.com/thunder-6-s3179.html

实施步骤：

1. 在实际运行页面分别独听三轨，并对比用户听到异常声的触发时刻；确认部署资产与本地版本一致。保留原声文件。
2. 试听真实雷声候选，选择适合窗后距离感的片段，保留自然起音/长尾；控制峰值，避免强压缩成持续轰鸣。
3. 新增独立、非循环的雷声音轨；与环境音量控制一致，人物说话时适度压低；静音为零，停止/重置可取消排期，销毁时释放音源。
4. 一次 lightning 事件排一次声音，使用音频时钟安排延迟；重复 ID 去重，限制重叠。天气事件独立于语音 epoch，打断台词不误切雷声。
5. 缺素材时跳过声音并记录诊断，不回退为随机噪声，也不阻塞进入场景。雷声不进入口型 analyser。
6. 耳机、电脑外放和目标手机试听；用真实麦克风检查雷声是否误触发 VAD。声学数值通过不代表自然度验收通过。

本轮仅准备素材和方案，没有接入运行时，雷声问题尚未修复。

## 9. 第一阶段验收场景

用户让她拿杯子；她看向杯子并伸手。分别在未接触、刚抓住、举起、靠近嘴、放回前打断。用户说“等等”“别拿了”“继续吧”或只是问问题，结果各自合理。保持安静后她能持杯/放杯、看雨，不强迫发起新事件。雷声到来时按当前动作作小反应，避免和用户说话争抢。

必须看到直接语音/点击路径和真实画面，不能只跑合成消息。记录首次注意反馈延迟、暂停到安全状态的延迟、指令到动作启动延迟；暂定本地视觉注意反馈目标小于 200ms（从活动检测触发算起，另记 VAD 本身延迟），不能把这个数当端到端承诺。取消不能重复提交接触事件，晚包不能污染新地点。持续安静至少观察两分钟，检查重复动作、无故插话和姿态僵住。

验证分层：状态机测试覆盖取消/接触竞争/晚包；浏览器直接交互检查遮挡与投影；目标手机检查触控命中、帧率、外放回声与声音自然度。第一阶段同时完成桌边互动和咖啡馆—屋檐下—返回的往返闭环，再用证据决定扩展范围。

## 10. 持久世界、地点往返与地图画布

### 10.1 用户体验

常驻一个小地图入口，显示当前地点；点击展开为可拖动、缩放的连续地图画布。地图代表这段相遇里共同去过的地方，初始只开放实际进入的咖啡馆。未到访区域保持纸面/雾状留白，不显示名称、内部细节或可进入按钮；地图不开成预先列出全部地点的关卡菜单。

通过对话或场景行为探索新地点；真正到达后，该区域解锁，地图异步绘制对应区域，保留已探索部分。地图生成中可以看到当前地点的临时标记与已到访轮廓；生成失败不让这个地点消失。已到访地点点击后显示预览、上次到访和“回到这里”，随后走统一转场流程。选中预览不立即移动，明确点击返回即表示用户的出发意图，不再要求额外对话确认。

打开地图时取消尚未开始的主动搭话，当前安全动作可继续；麦克风和用户主动说话仍可用。浏览地图本身不当成同意出发，也不触发新的世界事件。关闭后回到同一现场，不能重启相遇。移动端入口可触达，地点可从同一界面的已到访列表访问，避免小区域难点中或地图图片未加载时无法返回。

地图是一张可以逐步长大的画布。视觉呈现可以无缝，内部必须保存各区域、连接和命中边界，不能只存一张合成图片。

### 10.2 状态层与稳定身份

现有 `Story.history` 只保存有限的文字后果，`ClientSession` 存在进程内 Map 中；它们都不足以承担可返回的世界存档。新增独立持久世界，身份不依赖 Duplex 的 session_id、生成图片文件名或一段 scene_prompt。

| 实体       | 记录内容与规则                                                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| WorldSave  | worldId、ownerId、schemaVersion、revision、currentLocationId、人物状态、当前转场、创建/保存时间                                        |
| Location   | 稳定 locationId、名称/别名、模板/profile 版本、底图/前景/遮罩资产引用、可用交互、环境状态、首次/最近访问、visitCount、地点内已确认事实 |
| Object     | 世界内唯一 objectId、外观资产、持有者或地点/表面、摆放位置、可携带性、内容状态和 revision；归属只有一处                                |
| Connection | 两地点 ID、已实际通过的关系、路径状态；不让图片模型推断或修改连通性                                                                    |
| MapRegion  | locationId、固定画布坐标/边界、入口连接点、visited、绘图状态、地图图块资产及版本                                                       |
| TravelTask | travelId、originId、targetId、phase、intentId、sourceRevision、进入实例 ID、携带清单、准备/完成时间                                    |
| WorldEvent | 单调 seq、eventId、type、影响对象/地点、幂等键、已提交结果；仅记录结构化事实，不复制每帧骨骼                                           |

`locationId` 表示长期存在的地点；`sceneInstanceId` 每次进入地点重新生成，用于隔离旧动作/晚回包。返回同一个 locationId 时也必须有新的 sceneInstanceId。语音 session 可以重建，worldId 保持不变。

“回刚才那家咖啡馆”先在已访问地点 ID/别名中解析。多处地点无法唯一匹配时让用户选择；不以相似提示词的缓存命中代替身份判断。

人物情绪、已确认记忆、未回答的话以及持有物随世界延续。桌上物品、开关状态和地点事件留在地点里。第一版离开地点后不在后台模拟搬动物件、消耗咖啡或发生重大事件，返回时按存档恢复；之后若增加时间演化，也必须产生明确事件，而非让模型随口改写。

### 10.3 出发、取消与到达提交

单个世界一次只接受一个生效的 TravelTask。地图点击和自然语言共用该流程；重复点击按 intentId 去重。新请求若替换旧目的地，先明确取消未提交的旧行程，不能同时等待两张图并任意采用先返回的一张。

流程：请求 → 解析/验证地点与可返回条件 → 处理当前动作和携带物 → 准备目标资产 → 客户端预加载并准备显示 → 服务端持久提交到达 → 客户端应用对应版本、播放进入表现。

首次新地点可以在准备阶段创建候选记录和预留地图位置，但不标记 visited、不暴露给地图；新图生成完毕也不是到访。复访直接取原资产和状态，无需重新生图。预加载确认需匹配 travelId、目标资产版本和 sceneInstanceId，不能复用旧 ACK。

服务端到达事务原子更新：currentLocationId、visited/visitCount、路线、人物新场景实例及携带物归属，并写事件。客户端收到提交版本才将目标作为当前场景；若响应丢失，重连读取已提交快照。渲染准备成功与数据库提交不可能跨网络完全原子，故界面在最终确认前保持过渡状态，不提前宣布到达；提交后的显示失败允许重试加载或发起明确返回，不把 committed 偷改成 cancelled。

转场前已经实际完成的放杯动作即时记录，即使后来取消出发也不撤销。到达前取消：保留原地点，不解锁新区域，晚到的生图结果只入候选缓存。到达后“算了”：是一个新的返回请求，不回滚历史。断线重启后，未提交行程回到最后已提交地点，不重播正在喝水/抓取的半截动画。

已访问不等于永远可以无条件传送。第一版地图返回采用经过已知连接的省略行程，不要求完整走路演出；若路线或地点后来明确不可用，显示保存的原因，保留已访问区域。地图预览不允许凭空开启未知路线。

### 10.4 地图图片怎样逐块生成

地图外观采用统一的插画/俯视示意风格；进入场景的背景仍是人眼视角。两者共享 locationId 和地点描述，使用不同媒体资产，不能把人物视角照片直接当作地图地形。

首次到达提交后异步创建地图绘图任务：

1. 布局程序基于已知连接分配固定区域与入口，不与旧区域重叠；有确认方向则遵循，没有则采用示意排布，不宣称真实地理距离。
2. 根据地点描述、场景参考图、统一地图风格以及相邻已绘制区域生成候选图块。预留边缘衔接带；不要生成标签、按钮、玩家标记。
3. 现有 `arkImage({prompt, image})` 仅已确认有参考图输入；不能假定支持精确蒙版局部重绘。第一版即使生成器返回整幅候选，也只提取新区域及允许修改的接缝带，在本地合成，硬性保护旧区域内部像素。
4. 新图块通过尺寸、区域覆盖、接缝及地标检查后发布。地标、名称、当前地点、访问状态和点击边界由结构化数据和 UI 叠加，生成图片不能自行解锁地点或创建路径。
5. 按 worldId、regionId、区域 revision、邻接边缘版本和生成任务 ID 校验后写入。每个世界串行发布地图编辑或检测版本冲突后重试，避免两个新区域同时生成覆盖彼此。世界已重置或任务过期则不发布。

每个图块单独保存，地图总览只是可重建的缓存。画布越界时扩展坐标范围，原地点坐标和命中区不移动；第一版无需每到一地重生成整个大图。放大/缩小时视觉和命中区共享同一变换。

visited 与 mapArtworkStatus 分开：绘图失败保持可访问，显示朴素轮廓/场景缩略图，后台有限重试；地图任务既不阻塞角色对话，也不决定旅行成功。返回旧地点通常无需重绘地图；只有明确的外观变化才局部刷新对应区域，并保留资产版本。

### 10.5 存档、资产与恢复

第一版建议服务端 SQLite 保存结构化状态与事件，持久文件目录保存底图、遮罩、照片和地图图块，部署挂载持久卷。具体 SQLite 驱动在实施时按 Node 版本确认。浏览器只缓存显示状态并保存世界访问凭证，不能把 localStorage 当唯一存档。

世界访问权绑定服务端所有者/不透明恢复凭证，单独授权读取、返回、修改和获取私有生成资产；不能把上游语音 session_id 当世界访问令牌。暂不要求账号系统；同浏览器自动恢复，跨设备恢复需要另行设计，不能声称天然支持。

正式引用的生成资产必须从临时 `cache/media` 晋升到持久目录，文件写入/校验成功后才在数据库事务中引用。清理只删除无存档引用的候选和旧缓存，不删除已访问地点底图。原始版本保留，派生版通过新引用发布；资产引用使用 ID/相对路径而非绑定当前主机的 URL。

每次接触归属变化、到达、环境重要变化、地图发布和用户偏好变化都事务写入；骨骼、音量包络和逐帧位置不写库。保存 world revision 与事件序号，重连同步快照后只应用更新事件。写盘失败不向客户端报告保存成功，暂停后续世界变更并显示可理解的重试状态。

世界存档至少包含已确认对话事实、近期对话摘要/未回应内容，以便新建 Duplex 会话后注入上下文；不恢复旧音频缓冲和半截台词。当前多窗口仅允许一个写入客户端，其他窗口只读或明确接管，防止同一杯子被两处同时拿走。

现有 reset 的“整场归零”需与存档分开：普通刷新/重连继续当前世界；用户选择“重新开始”创建新 worldId 并保留旧存档，不隐式删除地图和地点。删除存档另设明确动作。第一版不迁移推测出来的旧内存历史；老会话保存为新世界时只能保留可确认的当前地点与事实。

### 10.6 新增模块和验收

建议模块：`server/src/world/store.ts`（事务/快照）、`locations.ts`（地点及物品）、`travel.ts`（转场）、`map.ts`（布局/生成发布），`shared/world.ts`（世界协议），`web/src/state/world.ts` 与 `web/src/ui/WorldMap.tsx`。目录为计划，不是已创建实现。与现有 session、director、genimg、scene.presented 桥接，不将地图状态塞进 StoryView 文案字段。

世界下行携带 snapshot/patch 及 revision，上行携带 travel.request/cancel 和 prepared 回报；地图只请求目标 locationId，不提交客户端自称到达的任意位置。地图画布先用简单矢量区域跑通访问/返回，再接生成图块，两者使用同一套状态和点击路径。

补充验收：

- 咖啡馆进入时只显示咖啡馆，未访问地区没有可用入口；提到一个地点、生成一张候选图都不解锁。
- 照片放咖啡馆桌上，去屋檐下，地图增加新区；点击咖啡馆返回，同一张照片仍在原桌上。携带离开的物品在旧地点不再出现。
- 重复返回同一地点不重复创建区域；地图图块生成期间可以说话/返回，不占据输入。
- 转场提交前取消不解锁；提交后断网恢复到已到达地点。重启服务后地点、物品、地图和当前所在位置一致。
- 图块生成失败、迟到、并发和重试不会覆盖旧区域；地图缩放/拖动后点击仍命中同一地点。
- 返回地点复用原资产且不再次付费生图；若原资产缺失，显示明确恢复状态，不静默生成不同地点冒充原地。
- 重新开始产生新世界，旧世界可保留；不同所有者不能读写彼此的世界或生成资产。
